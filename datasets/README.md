# Datasets

All files are generated by `make_datasets.py` (no randomness, so re-running gives identical files):

```bash
python3 datasets/make_datasets.py
```

In S3, the pipeline always reads **one fixed key: `input/orders.csv`**. For each test, copy the file you want over that key. Keep the other versions in `archive/`, where Rhombus can't see them.

## Cleaning rules (the contract the validation script checks)

1. Trim leading/trailing whitespace in every text column.
2. `customer_name`: Title Case.
3. `email`: lowercase. Drop rows where the email is missing or invalid.
4. `phone`: normalise to 10 digits `04XXXXXXXX` (convert `+61` to `0`, remove spaces and dashes). Blank is allowed.
5. `state`: uppercase code (NSW, VIC, QLD, WA, SA, TAS, ACT, NT). Map full names to codes. Blank is allowed.
6. `order_date`: output `YYYY-MM-DD`. Input is `MM/DD/YYYY` or `YYYY-MM-DD`. Drop impossible dates.
7. `amount_usd`: number with 2 decimal places. Drop rows where it's missing, non-numeric or negative.
8. `quantity`: whole number. Drop rows where it's non-numeric or less than 1.
9. `status`: lowercase, one of `pending`, `shipped`, `delivered`, `cancelled`. Drop anything else.
10. Drop rows with a missing `order_id`.
11. Remove duplicates by `order_id` **after** the steps above, keeping the first occurrence.

**Expected baseline output: 28 rows.** That's 41 rows, minus 2 exact duplicates, minus 1 near-duplicate, minus 10 invalid rows.

> 3. Convert email to lowercase, and remove rows where email is empty or not a valid email address.

> 5. Convert state to an uppercase Australian state code (NSW, VIC, QLD, WA, SA, TAS, ACT, NT), mapping full names like "New South Wales" to NSW. Keep rows with an empty state.
> 6. Convert order_date to YYYY-MM-DD. Input dates are either MM/DD/YYYY or YYYY-MM-DD. Remove rows with an invalid date.
> 7. Make amount_usd a number with 2 decimal places, and remove rows where it is empty, not a number, or negative.
> 8. Make quantity a whole number, and remove rows where it is not a number or is less than 1.
> 9. Convert status to lowercase and keep only pending, shipped, delivered, or cancelled.
> 10. Remove rows with an empty order_id.
> 11. After all the steps above, remove duplicate rows by order_id, keeping the first.

## Drifted versions

| File | Type | Change from baseline |
|---|---|---|
| `schema_drop_column.csv` | Schema | `phone` column removed |
| `schema_rename_column.csv` | Schema | `email` renamed to `email_address` |
| `schema_change_type.csv` | Schema | `order_id` changes from integer to string (`1001` → `ORD-1001`) |
| `schema_add_column.csv` | Schema | new `discount_code` column added at the end |
| `schema_combined.csv` | Schema | all four changes above at once |
| `semantic_dollars_to_cents.csv` | Semantic | `amount_usd` values ×100 (`49.99` → `4999`), header unchanged |
| `semantic_date_mmdd_to_ddmm.csv` | Semantic | dates written as `DD/MM/YYYY` (`01/22/2026` → `22/01/2026`), header unchanged |

### Why the semantic cases are detectable

- **Dollars → cents:** baseline amounts are between $5 and $499. After drift, most values are over 1,000, even though the column is still called `amount_usd`. A range check on the output catches it.
- **MM/DD → DD/MM:** most baseline dates have a day above 12, so the swapped values have a "month" of 13 or more. A correct parser must either reject them or silently mis-parse them, and both show up as a row-count drop or out-of-range dates. Dates like `02/03` → `03/02` stay valid but shift month, which is the dangerous, silent case, and the validation script compares those against the baseline.
